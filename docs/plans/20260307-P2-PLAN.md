# Prometheus AI P2 开发计划

**日期**: 2026-03-07
**阶段**: P2 - 生产优化与应用层开发
**周期**: 4-6 周
**前置条件**: P0-P6 已完成（核心模块 + 端到端测试）

---

## 背景

P0-P6 阶段已完成核心引擎开发：
- ✅ Ollama 本地推理集成
- ✅ 智能路由系统（意图分类 + 模型选择）
- ✅ 记忆系统（工作记忆 + 情景记忆 + 知识库）
- ✅ Daemon Mind（预测 + 信念 + 反思）
- ✅ 经济皮层（成本追踪 + ROI 优化）
- ✅ 端到端集成测试

**P2 目标**: 在核心引擎基础上，构建生产级应用层，包括 CLI 工具、HTTP API 服务、性能优化、监控系统和部署方案。

## Phase 1: CLI 工具增强（Week 1-2）

### 目标
将现有 CLI 从基础对话工具升级为功能完整的生产级命令行界面。

### Task 1.1: 交互式对话模式
- **文件**: `cli/src/interactive.rs`（新建）
- **功能**:
  - REPL 循环（Read-Eval-Print-Loop）
  - 多行输入支持（Ctrl+D 结束）
  - 历史记录（上下箭头导航）
  - 自动补全（命令和参数）
  - 彩色输出（用户/助手/系统消息）
- **依赖**: `rustyline` crate
- **TDD**:
  - 测试 REPL 循环正常工作
  - 测试历史记录保存和加载
  - 测试多行输入解析
- **验证**: `cargo run --bin prometheus-cli -- interactive`

### Task 1.2: 会话管理
- **文件**: `cli/src/session.rs`（新建）
- **功能**:
  - 会话创建/列表/删除/恢复
  - 会话元数据（创建时间、消息数、成本）
  - 会话导出（JSON/Markdown）
  - 会话搜索（按内容/时间）
- **存储**: SQLite（`~/.prometheus/sessions.db`）
- **TDD**:
  - 测试会话 CRUD 操作
  - 测试会话导出格式
  - 测试会话搜索准确性
- **验证**: `prometheus-cli session list/new/delete/export`

### Task 1.3: 配置管理
- **文件**: `cli/src/config.rs`（新建）
- **功能**:
  - 配置文件（`~/.prometheus/config.toml`）
  - 模型选择（默认对话模型、embedding 模型）
  - 路由策略（Balanced/CostOptimized/QualityFirst）
  - 预算限制（日/月预算、告警阈值）
  - Ollama 连接配置（URL、超时）
- **TDD**:
  - 测试配置加载和保存
  - 测试配置验证
  - 测试默认配置生成
- **验证**: `prometheus-cli config show/set/reset`

### Task 1.4: 统计与报告
- **文件**: `cli/src/stats.rs`（新建）
- **功能**:
  - 成本统计（日/周/月）
  - 模型使用统计（调用次数、平均延迟、ROI）
  - 会话统计（总数、平均长度、质量分数）
  - 导出报告（JSON/CSV）
- **TDD**:
  - 测试统计数据计算准确性
  - 测试报告生成格式
- **验证**: `prometheus-cli stats --daily/--weekly/--monthly`

### Task 1.5: 插件管理
- **文件**: `cli/src/plugin.rs`（新建）
- **功能**:
  - 插件列表/安装/卸载/启用/禁用
  - 插件信息查看（版本、作者、描述）
  - 插件配置管理
- **TDD**:
  - 测试插件加载和卸载
  - 测试插件配置读写

- **文件**: `server/src/main.rs`（新建）

  - 路由注册
  - 中间件（日志、CORS、认证）

- **TDD**:

  - 测试路由注册
  - 测试中间件执行顺序
- **验证**: `cargo run --bin prometheus-server`

### Task 2.2: 对话 API
- **文件**: `server/src/routes/chat.rs`（新建）
- **端点**:
  - `POST /api/v1/chat` - 发送消息
  - `POST /api/v1/chat/stream` - 流式对话（SSE）
  - `GET /api/v1/chat/sessions` - 获取会话列表
  - `GET /api/v1/chat/sessions/:id` - 获取会话详情
  - `DELETE /api/v1/chat/sessions/:id` - 删除会话
- **请求/响应格式**: JSON
- **TDD**:
  - 测试对话 API 正确性
  - 测试流式响应
  - 测试会话管理 API
- **验证**: `curl -X POST http://localhost:8080/api/v1/chat`

### Task 2.3: 记忆 API
- **文件**: `server/src/routes/memory.rs`（新建）
- **端点**:

  - `GET /api/v1/memory/knowledge` - 搜索知识库
  - `GET /api/v1/memory/working` - 获取工作记忆
- **TDD**:
  - 测试记忆搜索准确性

- **验证**: `curl http://localhost:8080/api/v1/memory/search`

### Task 2.4: 统计 API

## Phase 3: 性能优化（Week 3-4）

### 目标
优化系统性能，降低延迟，提高吞吐量。

### Task 3.1: 向量检索优化
- **文件**: `core/src/memory/episodic.rs`, `core/src/memory/knowledge.rs`
- **优化**:
  - 使用 HNSW 索引（`hnswlib-rs`）替代暴力搜索
  - 批量 embedding 生成
  - 向量缓存（LRU cache）
- **基准测试**:
  - 1000 条记忆检索延迟 < 50ms
  - 10000 条记忆检索延迟 < 200ms
- **TDD**:
  - 测试 HNSW 索引构建
  - 测试检索准确性（召回率 > 95%）
- **验证**: `cargo bench --bench memory_search`

### Task 3.2: 并发处理优化
- **文件**: `core/src/orchestrator.rs`
- **优化**:
  - 异步并发处理（意图分类 + 记忆检索）
  - 连接池（数据库、HTTP 客户端）
  - 请求批处理
- **基准测试**:
  - 单请求延迟 < 500ms
  - 并发 10 请求吞吐量 > 15 QPS
- **TDD**:
  - 测试并发安全性
  - 测试连接池复用
- **验证**: `cargo bench --bench concurrent_requests`

### Task 3.3: 缓存策略
- **文件**: `core/src/cache.rs`（新建）
- **功能**:
  - LLM 响应缓存（相似问题复用）
  - Embedding 缓存（相同文本复用）
  - 路由决策缓存
- **缓存策略**: LRU + TTL
- **TDD**:
  - 测试缓存命中率
  - 测试缓存过期
- **验证**: 缓存命中率 > 30%

### Task 3.4: 内存优化
- **优化**:
  - 减少不必要的克隆（使用 `Arc` 和 `Cow`）
  - 流式处理大文件
  - 及时释放资源
- **基准测试**:
  - 内存占用 < 200MB（空闲）
  - 内存占用 < 500MB（高负载）
- **验证**: `cargo run --release` + `htop`

## 风险与应对

### 风险 1: 性能优化效果不达标
- **应对**: 提前进行性能基准测试，及时调整优化策略
- **备选方案**: 使用更高效的数据结构（如 `faiss`）

### 风险 2: API 设计变更频繁
- **应对**: 使用版本化 API（`/api/v1/`），保持向后兼容
- **备选方案**: 提供 API 迁移指南

### 风险 3: 部署环境差异大
- **应对**: 提供多种部署方案（Docker/源码/二进制）
- **备选方案**: 提供详细的故障排查文档

### 风险 4: 文档维护成本高
- **应对**: 使用自动化工具生成 API 文档
- **备选方案**: 社区贡献文档
