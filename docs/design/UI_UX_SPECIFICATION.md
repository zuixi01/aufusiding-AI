## 一、设计理念

### 1.1 AI 操作系统概念

Prometheus 不是聊天机器人。它是一个 **24 小时环境感知 AI 操作系统**。

传统 AI 助手（ChatGPT、通义千问、豆包等）的核心交互范式是"对话框"——用户输入文字，AI 返回文字。Prometheus 彻底抛弃了这一范式。它的主屏幕是一个 **3D 机器人头像居中、8 个核心 App 图标沿椭圆轨道环绕运行** 的"AI 桌面"，如同行星围绕恒星运转。

每个核心能力被封装为独立的 App：

| 序号 | App | 图标 | 职责 |
|------|-----|------|------|
| 1 | 语音交互 | 🎙 | 自然语言对话、语音指令、声纹识别 |
| 2 | 智能路由 | 🧭 | 本地/云端模型调度、成本优化、延迟控制 |
| 3 | 记忆系统 | 🧠 | 短期/长期/情景记忆管理、语义检索 |
| 4 | Agent 集群 | 🤖 | 多 Agent 协作、DAG 任务编排、质量门禁 |
| 5 | 普罗万物 | 🌐 | IoT 设备管理、智能场景、自动化规则 |
| 6 | 安全隐私 | 🛡 | 数据脱敏、权限管理、GDPR 合规 |
| 7 | 插件系统 | 🔌 | WASM 插件加载、插件市场、生命周期管理 |
| 8 | 工具链 | 🧩 | 外部工具调用、Function Calling 统计 |

这种设计让用户一眼就能感知 AI 系统的全貌——它不是一个等待提问的黑盒，而是一个始终运转的有机体。

### 1.2 与主流 AI 助手的根本区别

| 维度 | ChatGPT / 通义千问 / 豆包 | Prometheus AI |
|------|---------------------------|---------------|
| **主屏** | 空白对话框 + 输入栏 | 3D 机器人头像 + 8 个环绕 App 图标 |
| **交互入口** | 文字输入为主，语音为辅 | 语音优先，App 图标点击，手势操控 |
| **导航模型** | 线性对话历史列表 | 空间化桌面 + 全屏沉浸详情页 |
| **环境感知** | 无（被动等待用户输入） | 24h 环境感知：时间、地点、设备、模式自动切换 |
| **状态表达** | 仅"正在输入…"文字提示 | 3D 机器人表情 + 呼吸动画 + 模式主题色 |
| **能力展示** | 隐藏在对话中，用户需主动发现 | 8 个 App 图标始终可见，能力一目了然 |
| **多任务** | 单线程对话 | Agent 集群并行执行，DAG 任务图可视化 |
| **个性化** | 有限的自定义指令 | 三层记忆系统 + 5 种模式感知主题 |
| **设备联动** | 无 | IoT 设备网格 + 智能场景自动化 |
| **隐私控制** | 设置页中的开关 | 独立安全隐私 App，实时脱敏可视化 |

### 1.3 设计原则

#### Calm Technology（宁静技术）

Prometheus 遵循 Mark Weiser 提出的 Calm Technology 理念：技术应退居外围（periphery），仅在需要时进入注意力中心（center）。

具体体现：
- 主屏信息密度极低，仅展示机器人状态和 App 图标
- 通知不弹窗打断，而是通过机器人表情变化和图标微动暗示
- Sleep 模式下界面近乎全黑，仅保留时间和呼吸动画
- 声音反馈使用自然音效（如轻敲陶瓷、风铃），而非电子提示音

#### 有机动效（Organic Motion）

所有动画模拟自然界的运动规律，而非机械的线性插值：

- **呼吸感**：机器人头像持续微幅缩放，模拟生命体的呼吸节奏
- **轨道运动**：App 图标沿椭圆轨道缓慢运行，模拟天体运动
- **弹性回弹**：交互反馈使用弹性缓动曲线，模拟物理材质的弹性
- **流体过渡**：页面切换使用流体变形动画，而非硬切或滑动

#### 模式感知（Context-Aware Theming）

界面根据用户当前情境自动调整视觉主题和信息密度：

- **时间感知**：根据日出/日落自动切换 Light/Dark Mode
- **场景感知**：Home/Work/Sleep/Driving/Focus 五种模式自动识别
- **设备感知**：根据连接的 IoT 设备调整可用操作
- **情绪感知**：通过语音语调和使用模式推断用户状态，调整交互节奏

## 二、设计系统

### 2.1 配色方案

Prometheus 采用暖色系配色，传达温暖、可信赖、有生命感的视觉印象。拒绝冷冰冰的科技蓝，拥抱大地色系的自然质感。

每种感知模式拥有独立的强调色，用于机器人眼睛、轨道光晕、状态栏指示等关键视觉元素：

### 2.4 动效语言

Prometheus 的动效设计追求"有机感"——所有运动模拟自然界的物理规律，避免机械的线性运动。

#### 缓动曲线

```css
:root {
  /* 缓慢呼吸 — 用于循环动画（呼吸、轨道运动、环境光变化） */
  --ease-ambient:  cubic-bezier(0.25, 0.1, 0.25, 1.0);

  /* 灵敏响应 — 用于用户交互反馈（点击、拖拽、滑动） */
  --ease-respond:  cubic-bezier(0.16, 1, 0.3, 1);

  /* 柔和归位 — 用于元素回到静止状态（释放、关闭、收起） */
  --ease-settle:   cubic-bezier(0.33, 1, 0.68, 1);

  /* 弹性回弹 — 用于强调性反馈（成功、完成、弹出） */
  --ease-bounce:   cubic-bezier(0.34, 1.56, 0.64, 1);

  /* 流体展开 — 用于页面展开和层级过渡 */
  --ease-expand:   cubic-bezier(0.19, 1, 0.22, 1);
}
```

#### 时长规范

```css
:root {
  /* 微交互 — 按钮状态、开关切换、Hover 效果 */
  --duration-micro:     150ms;
  --duration-micro-max: 200ms;

  /* 元素过渡 — 卡片展开、列表项进入、Tab 切换 */
  --duration-element:     300ms;
  --duration-element-max: 400ms;

  /* 层级过渡 — 页面切换、模态弹出、全屏展开 */
  --duration-layer:     500ms;
  --duration-layer-max: 700ms;

  /* 环境循环 — 呼吸动画、轨道运动、背景渐变 */
  --duration-ambient:     3000ms;
  --duration-ambient-max: 6000ms;

  /* 模式转换 — 主题色切换、机器人表情变化、整体氛围过渡 */
  --duration-mode:     1200ms;
  --duration-mode-max: 1800ms;
}
```

#### 核心动画定义

```css
/* 机器人呼吸动画 */
@keyframes robot-breathe {
  0%, 100% { transform: scale(1.0); }
  50%      { transform: scale(1.02); }

  animation: robot-blink 150ms var(--ease-respond);

/* App 图标轨道运动 */
@keyframes orbit-rotate {
  from { transform: rotate(0deg) translateX(var(--orbit-radius)) rotate(0deg); }
  to   { transform: rotate(360deg) translateX(var(--orbit-radius)) rotate(-360deg); }
}
.app-icon-orbit {
  animation: orbit-rotate 60s linear infinite;
}

/* 模式切换过渡 */
.mode-transition {
  transition:
    background-color var(--duration-mode) var(--ease-ambient),
    color var(--duration-mode) var(--ease-ambient),
    box-shadow var(--duration-mode) var(--ease-ambient);

/* 页面展开动画 */
@keyframes page-expand {

    clip-path: circle(32px at var(--origin-x) var(--origin-y));
    opacity: 0.8;
  }
  to {
    clip-path: circle(150% at var(--origin-x) var(--origin-y));
    opacity: 1;
  }
}
.page-enter {
  animation: page-expand var(--duration-layer) var(--ease-expand) forwards;
}
```

### 2.5 图标系统

#### Phosphor Icons (Duotone) 规范

Prometheus 使用 **Phosphor Icons** 图标库的 **duotone** 风格，温暖友好，与大地色系设计语言高度契合。

```
图标库:       Phosphor Icons (https://phosphoricons.com)
风格权重:     Duotone（双色调 — 主色 + 30% 透明度辅色）
CDN:          @phosphor-icons/web@2/src/duotone/style.css
基础网格:     24 × 24 px
CSS 类名:     class="ph-duotone ph-{icon-name}"
尺寸控制:     font-size（继承或内联指定）
颜色控制:     color（继承 CSS 变量）
辅色透明度:   --ph-duotone-opacity: 0.3
```

#### 图标风格特征

- **圆润**：Phosphor 图标天然使用圆角处理，避免尖锐几何感
- **温暖**：duotone 双色调风格自带层次感，比纯线条更有温度
- **一致**：所有图标视觉重量一致，在 24px 网格中占据相近面积
- **可辨识**：每个图标在 16px 缩小尺寸下仍可清晰辨认

## 四、模式感知主题

Prometheus 根据用户当前情境自动切换 5 种感知模式，每种模式拥有独立的视觉主题、信息密度和交互行为。模式切换可自动触发（基于时间、位置、设备状态），也可手动切换。

### 4.1 模式总览

| 维度 | 🏠 Home | 💼 Work | 🌙 Sleep | 🚗 Driving | 🎯 Focus |

## 五、3D 机器人头像规格

机器人头像是 Prometheus 的灵魂。它不是装饰性的吉祥物，而是系统状态的实时可视化载体——通过表情、动画、材质变化传达 AI 的运行状态和情感。

### 5.1 基础规格

```
风格:       3D 拟物渲染，金属/陶瓷混合材质
造型:       圆润的机器人头部，略带卡通比例（头大身小）
            无身体，仅头部 + 短颈部
            双眼为圆形发光体，嘴部为简化的弧线

尺寸:
  Mobile 主屏:     160 × 160 px
  Desktop 主屏:    200 × 200 px
  语音对话界面:    200 × 200 px（Mobile）/ 240 × 240 px（Desktop）
  Sleep 模式:      120 × 120 px（缩小）
  Dock 栏图标:     32 × 32 px（2D 简化版）
  通知头像:        40 × 40 px（2D 简化版）
```

### 5.2 材质规格

```
主体材质（头部外壳）:
  类型:       PBR (Physically Based Rendering)
  基础色:     根据模式变化（见下方模式材质表）
  金属度:     0.6（金属/陶瓷混合感）
  粗糙度:     0.3（半光泽，有柔和反射）
  法线贴图:   微弱的陶瓷纹理
  环境遮蔽:   启用，增加立体感

眼睛材质:
  类型:       Emissive（自发光）
  形状:       正圆形，直径约为头部宽度的 18%
  间距:       两眼间距约为头部宽度的 30%
  颜色:       跟随模式强调色
  发光强度:   1.0（默认）→ 1.5（Listening）→ 0.3（Sleeping）
  光晕:       径向模糊，半径为眼睛直径的 150%

嘴部:
  类型:       凹陷弧线，非独立几何体
  宽度:       约为头部宽度的 25%
  位置:       眼睛下方，头部下 1/3 处
  动画:       通过 Blend Shape / Morph Target 控制开合

天线/装饰（可选）:
  位置:       头顶中央，短天线造型
  材质:       磨砂金属（Metallic: 0.8, Roughness: 0.5）
  动画:       随机器人情绪微微摆动
```

### 5.5 渲染技术规格

```

  CPU 占用:   ≤ 5%（空闲态）

降级策略:
  低端设备:   使用预渲染的 Sprite Sheet 动画替代实时 3D
  省电模式:   切换为静态 2D 图标 + CSS 动画
  无 WebGL:   使用 Lottie 动画替代
```

### 6.2 过渡动画

#### App 图标点击 → 全屏展开

```
触发:     点击主屏上的 App 图标

Phase 1 — 图标响应 (0-150ms):
  - 图标 scale: 1.0 → 0.95（按下反馈）
  - 触觉反馈（轻触）

Phase 2 — 圆形展开 (150-600ms):
  - 以图标中心为原点，clip-path circle 从 32px 扩展到覆盖全屏
  - 详情页内容从 opacity 0 → 1，scale 0.95 → 1.0
  - 主屏其他元素 opacity 1 → 0（200ms 延迟后开始）
  - 缓动: var(--ease-expand)

Phase 3 — 内容就位 (600-800ms):
  - 详情页导航栏从上方滑入
  - 内容区域元素依次淡入（stagger 50ms）
  - 底部操作栏从下方滑入

总时长: 约 700-800ms
```

#### 返回 → 收缩回位

```
触发:     点击返回按钮 / 左边缘右滑超过阈值

Phase 1 — 内容退出 (0-200ms):
  - 详情页内容 opacity 1 → 0
  - 内容 scale 1.0 → 0.98

Phase 2 — 圆形收缩 (200-600ms):
  - clip-path circle 从全屏收缩回图标位置和大小
  - 主屏元素 opacity 0 → 1
  - 缓动: var(--ease-settle)

Phase 3 — 图标归位 (600-700ms):
  - 图标 scale 恢复 1.0
  - 轨道动画恢复
  - 机器人呼吸动画恢复

总时长: 约 600-700ms
```

#### 控制中心弹出

```
触发:     从顶部下滑 / 点击 Dock 控制按钮

弹出动画 (0-500ms):
  - 毛玻璃背景 opacity 0 → 1
  - Sheet 从上方滑入，带弹性回弹
  - 内容元素依次淡入（stagger 30ms）
  - 缓动: var(--ease-bounce)

收起动画 (0-400ms):
  - Sheet 向上滑出
  - 毛玻璃背景 opacity 1 → 0
  - 缓动: var(--ease-settle)
```

#### 模式切换全局过渡

```
触发:     在控制中心选择新模式

详见 4.7 节"模式切换动画"
总时长: 1200-1800ms
涉及: 背景色、强调色、机器人表情、状态语、App 图标颜色
```

### 6.3 触觉反馈

Prometheus 使用分层触觉反馈系统，通过不同强度和模式的振动增强交互的物理感。

```
触觉反馈等级:

Light（轻触）:
  强度:     UIImpactFeedbackGenerator.style.light (iOS)
            HapticFeedbackConstants.CLOCK_TICK (Android)
  用途:     按钮点击、开关切换、Tab 切换、列表项选择
  时长:     ~10ms

Medium（中等）:
  强度:     UIImpactFeedbackGenerator.style.medium (iOS)
            HapticFeedbackConstants.CONTEXT_CLICK (Android)
  用途:     模式切换确认、App 图标点击、任务完成
  时长:     ~20ms

Heavy（重触）:
  强度:     UIImpactFeedbackGenerator.style.heavy (iOS)
            HapticFeedbackConstants.LONG_PRESS (Android)
  用途:     长按触发、拖拽开始、错误提示
  时长:     ~30ms

Success（成功）:
  强度:     UINotificationFeedbackGenerator.success (iOS)
            自定义模式 (Android)
  用途:     任务完成、番茄钟结束、场景激活成功
  模式:     轻-重 双段振动

Warning（警告）:
  强度:     UINotificationFeedbackGenerator.warning (iOS)
            自定义模式 (Android)
  用途:     错误发生、安全告警、预算超限
  模式:     重-轻-重 三段振动

Selection（选择）:
  强度:     UISelectionFeedbackGenerator (iOS)
            HapticFeedbackConstants.KEYBOARD_TAP (Android)
  用途:     滚动选择器、轨道拖拽中的刻度感
  时长:     ~5ms
```

#### 触觉反馈规则

```
1. Sleep 模式下禁用所有触觉反馈
2. Focus 模式下仅保留 Light 级别
3. Driving 模式下增强所有反馈强度（+50%）
4. 用户可在设置中完全关闭触觉反馈
5. 循环动画（呼吸、轨道）不触发触觉反馈
```

### 6.4 无障碍设计

Prometheus 致力于让所有用户都能使用，包括视觉、听觉、运动和认知障碍用户。

#### 视觉无障碍

```
颜色对比度:
  - 所有文字/背景组合满足 WCAG 2.1 AA 标准
  - 主文字对比度 ≥ 4.5:1
  - 大文字（18px+ 或 14px+ Bold）对比度 ≥ 3:1
  - 非文字元素（图标、边框）对比度 ≥ 3:1

色盲友好:
  - 不仅依赖颜色传达信息，同时使用图标/文字/形状
  - Agent 状态: 颜色 + 图标（✓ ● ◐ ✗）
  - 安全等级: 颜色 + 数字 + 文字标签

动态字体:
  - 支持系统级字体大小调整（iOS Dynamic Type / Android SP）
  - 所有文字使用相对单位（rem/sp）
  - 布局在 200% 字体放大下不破裂

高对比模式:
  - 检测系统高对比模式设置
  - 自动增强边框、阴影、文字对比度
  - 移除半透明效果，使用实色背景

减少动画:
  - 检测 prefers-reduced-motion 媒体查询
  - 禁用: 轨道运动、呼吸动画、粒子效果、页面过渡动画
  - 保留: 必要的状态变化（如加载指示器）
  - 所有过渡改为即时切换（duration: 0ms）
```

#### 屏幕阅读器支持

```
语义化标记:
  - 所有交互元素有明确的 aria-label
  - App 图标: aria-label="语音交互 App，点击进入"
  - 机器人头像: aria-label="Prometheus AI 助手，当前状态: 空闲，点击开始语音对话"
  - 模式徽章: aria-label="当前模式: 居家模式"

焦点管理:
  - 页面切换后焦点自动移至新页面标题
  - 模态弹出时焦点陷阱（Focus Trap）
  - 关闭模态后焦点返回触发元素
  - Tab 键顺序遵循视觉布局逻辑

实时区域:
  - 状态语变化: aria-live="polite"
  - Agent 任务完成: aria-live="polite"
  - 错误告警: aria-live="assertive"
  - 语音转写: aria-live="polite"

3D 机器人替代文本:
  - 为屏幕阅读器提供文字描述替代 3D 渲染
  - "Prometheus AI 助手头像，当前表情: 微笑，眼睛颜色: 金色"
  - 表情变化时更新描述
```

#### 运动无障碍

```
触控目标:
  - 所有可交互元素最小尺寸 44 × 44 px（WCAG 2.5.5）
  - Driving 模式下增大至 64 × 64 px
  - 相邻触控目标间距 ≥ 8px

替代输入:
  - 支持外接键盘完整操作（见 7.2 节）
  - 支持 Switch Control（iOS）/ Switch Access（Android）
  - 语音控制: 所有操作可通过语音指令完成

手势替代:
  - 所有手势操作都有对应的按钮替代
  - 下滑打开控制中心 → 也可点击 Dock 按钮
  - 左滑删除 → 也可长按显示菜单
  - 双指缩放 → 也可使用 +/- 按钮
```

#### 认知无障碍

```
简洁模式:
  - 可选的简洁界面模式，减少视觉元素
  - 隐藏轨道动画，App 图标改为静态网格布局
  - 减少状态语的变化频率
  - 使用更直白的文字描述

一致性:
  - 所有页面遵循统一的导航模式
  - 返回按钮始终在左上角
  - 操作确认始终使用相同的弹窗样式
  - 颜色语义一致（sage=成功, ember=错误）

错误恢复:
  - 所有破坏性操作（删除、清除）需二次确认
  - 提供撤销操作（5s 内可撤销）
  - 错误信息包含具体的修复建议
```

### 7.5 性能适配策略

```
设备分级:

Tier 1 — 旗舰设备（iPhone 14+, Pixel 7+, M1+ Mac）:
  - 完整 3D 渲染 60fps
  - 所有动画效果
  - 毛玻璃 backdrop-filter
  - 粒子效果
  - 实时阴影

Tier 2 — 中端设备（iPhone 11-13, Pixel 5-6, 普通笔记本）:
  - 3D 渲染 30fps
  - 简化动画（移除粒子效果）
  - 毛玻璃效果降级为半透明
  - 静态阴影

Tier 3 — 低端设备（iPhone SE, 入门 Android, 旧笔记本）:
  - 2D Sprite Sheet 替代 3D
  - 仅保留必要动画（状态切换）
  - 移除毛玻璃效果，使用实色
  - 移除阴影
  - 减少 DOM 节点数

检测策略:
  - 使用 navigator.hardwareConcurrency 检测 CPU 核心数
  - 使用 WebGL 渲染基准测试检测 GPU 能力
  - 使用 navigator.deviceMemory 检测内存
  - 根据检测结果自动选择 Tier
  - 用户可在设置中手动覆盖
```
