## 二、开发策略

### 核心原则
1. **聚焦 MVP**：优先打通核心对话流程（本地推理 + 云端 API + 记忆）
2. **渐进增强**：在可用基础上逐步添加高级功能
3. **质量优先**：每个模块完成后必须有测试覆盖
4. **用户价值**：优先开发用户可感知的功能

### 为什么不重写？
1. 已有 6599 行高质量 Rust 代码，架构设计合理
2. 核心对话流程已打通，重写需要 4-6 周
3. 现有代码编译通过，有测试覆盖
4. 在现有基础上开发可节省 60% 时间

**任务清单**:
- [ ] **T1.1.1**: 集成 llama.cpp Rust 绑定

## 四、技术选型

### 4.1 本地推理引擎

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| llama.cpp | 跨平台、成熟、快速 | C++ FFI 复杂 | ⭐⭐⭐⭐⭐ |
| candle | 纯 Rust、易集成 | 生态较小 | ⭐⭐⭐⭐ |
| MLX (macOS) | Apple Silicon 优化 | 仅 macOS | ⭐⭐⭐⭐⭐ |

**决策**: llama.cpp（跨平台） + MLX（macOS 专属）

### 4.2 向量数据库

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| sqlite-vec | 轻量、嵌入式 | 功能有限 | ⭐⭐⭐⭐⭐ |
| qdrant | 功能强大 | 需独立服务 | ⭐⭐⭐ |
| milvus | 企业级 | 过重 | ⭐⭐ |

**决策**: sqlite-vec（Phase 1），可选 qdrant（Phase 2+）

### 4.3 WASM 运行时

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| wasmtime | 官方、安全、快速 | API 复杂 | ⭐⭐⭐⭐⭐ |
| wasmer | 易用 | 生态较小 | ⭐⭐⭐⭐ |

**决策**: wasmtime
