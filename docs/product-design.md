# Prometheus (普罗米) — 产品设计方案

### 1. 产品定位

> **一句话**: 人人都能用的 AI 助理 — 本地优先、隐私安全、零门槛。

**核心差异化:**

| 维度 | Prometheus (普罗米) 的做法 |
|------|---------------------------|
| 成本 | 80%+ 对话由本地模型处理，月均 <$3 |
| 上手 | 下载 → 打开 → 对话，3 步完成 |
| 隐私 | 数据分级 + 本地加密 + 用户可控 |
| 离线 | 断网也能用 (本地模型) |
| 跨平台 | iOS / Android / macOS / Windows / Linux 原生 App |

**目标用户:**

| 用户群 | 痛点 | Prometheus 方案 |
|--------|------|-----------------|
| 普通用户 | ChatGPT 要钱，隐私担忧 | 免费本地模型 + 数据不出设备 |
| 开发者 | 需要编程助手但不想付 $20/月 | 本地代码模型 + 按需云端 |
| 企业员工 | 公司禁止用外部 AI | 私有部署 + 数据合规 |
| 智能家居用户 | 各平台 App 割裂 | 统一 AI 入口控制所有设备 |
| 隐私敏感用户 | 不信任云端 AI | 纯本地模式，零数据外传 |

### 核心模块设计

#### 1. 智能路由器 (Smart Router) — 省钱的关键

```
用户输入 → 意图分类 (本地小模型, <1ms)
                │
                ├─ 简单问答/闲聊 → 本地 7B 模型 (免费)
                ├─ 中等复杂度   → 本地 14B 模型 (免费) 或 云端便宜模型
                ├─ 复杂推理     → 云端 Claude/GPT (按需付费)
                └─ 代码/长文    → 云端大模型 + 本地缓存
```

核心策略：
- 80% 的日常对话由本地模型处理 → 零成本
- 只有真正需要强推理的任务才调用云端 API
- 用户可手动切换 "省钱模式" / "最强模式" / "自动模式"
- 对话上下文压缩：本地模型做摘要，减少云端 token 消耗

#### 2. 一键启动体验

**手机 (iOS/Android):**
- App Store / Google Play 下载
- 打开 App → 选择语言 → 开始对话 (3 秒内)
- 首次使用自动下载 2GB 轻量本地模型 (Wi-Fi 下后台完成)
- 可选：登录云端账号解锁高级模型

**电脑 (macOS/Windows/Linux):**
- 下载 .dmg / .exe / .AppImage
- 双击安装，双击打开
- 系统托盘常驻，随时唤起
- 快捷键全局唤起 (如 Ctrl+Space)

│  │  • 智能压缩: 本地小模型做摘要 (免费)                   │  │

│  ┌───────────────────────────────────────────────────────┐  │
│  │  L2: 情景记忆 (Episodic Memory)                       │  │
│  │  • 过去对话的结构化摘要 (不只是原文向量化)              │  │
│  │  • 提取: 事件 + 时间 + 情感 + 结论                    │  │

│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  L3: 语义记忆 (Semantic Memory)                        │  │
│  │  • 文档/笔记/文件的向量索引                            │  │
│  │  • 混合搜索 (向量 + BM25) + MMR 多样性重排             │  │
│  │  • Embedding 100% 本地                                 │  │
│  │    → 用 GTE-small/BGE-small (本地, 50MB, 免费)         │  │
│  └───────────────────────────────────────────────────────┘  │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  L4: 主动回忆 (Proactive Recall)                       │  │
│  │  • 不等你问，主动想起相关的事                          │  │
│  │  • 例: 你说"我要写个API" → 主动提醒                    │  │
│  │    "上次你提到过偏好用 FastAPI 而不是 Flask"            │  │
│  │  • 例: 检测到日期 → "你上周说3月1号要交报告"           │  │
│  │  → 触发器: 关键词匹配 + 时间关联 + 情感关联            │  │
│  │  → 实现: 本地小模型判断是否值得提醒 (避免打扰)         │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘

**PrometheusPlugin trait 定义：**

```rust
// 插件开发者只需实现这个 trait
#[prometheus_plugin]
trait PrometheusPlugin {
    /// 插件元信息
    fn manifest() -> PluginManifest;

    /// 注册工具 (供 AI 调用)
    fn register_tools() -> Vec<ToolDefinition>;

    /// 处理工具调用
    fn handle_tool_call(name: &str, args: Value) -> Result<Value>;

    /// 可选: 处理消息事件
    fn on_message(_msg: &Message) -> Option<Response> { None }

    /// 可选: 处理生命周期事件
    fn on_event(_event: &Event) { }
}
```

#### 6. 安全沙箱系统

**Prometheus 的安全沙箱设计：**

```
┌─────────────────────────────────────────────────────────┐
│              Prometheus 安全沙箱 (多层防护)               │
│                                                         │
│  ┌─────────────────────────────────────────────────┐    │
│  │  第一层: OS 原生沙箱 (零开销)                    │    │
│  │  • macOS/iOS: App Sandbox + XPC                  │    │
│  │  • Android: SELinux + 进程隔离                   │    │
│  │  • Linux: Landlock LSM + seccomp-bpf             │    │
│  │  • Windows: AppContainer                         │    │
│  │  → 不需要 Docker，系统内核级隔离                  │    │
│  └─────────────────────────────────────────────────┘    │
│                                                         │
│  ┌─────────────────────────────────────────────────┐    │
│  │  第二层: WASM 沙箱 (插件隔离)                    │    │
│  │  • 插件运行在 Wasmtime 沙箱中                    │    │
│  │  • 默认无文件系统/网络访问                       │    │
│  │  • 通过 Capability 授权: fs_read / net / exec    │    │
│  │  • 内存限制 + CPU 时间限制                       │    │
│  └─────────────────────────────────────────────────┘    │
│                                                         │
│  ┌─────────────────────────────────────────────────┐    │
│  │  第三层: 代码执行沙箱 (AI 编程用)                │    │
│  │  • 轻量级: 使用 Firecracker microVM (2MB 内核)   │    │
│  │    或 gVisor (无需完整 VM)                       │    │
│  │  • 桌面端: Firecracker/gVisor 按需启动           │    │
│  │  • 手机端: 受限解释器 (Python/JS WASM 版)        │    │
│  │  • 文件系统: 只读挂载 + 临时写入区               │    │
│  │  • 网络: 默认断网，需要时白名单放行              │    │
│  └─────────────────────────────────────────────────┘    │
│                                                         │
│  ┌─────────────────────────────────────────────────┐    │
│  │  第四层: 权限审批 (用户可控)                     │    │
│  │  • 三级权限: 安全(自动) / 敏感(确认) / 危险(拒绝)│    │
│  │  • 可视化权限面板: 看到每个操作的风险等级        │    │
│  │  • 一键撤销: 随时收回已授予的权限                │    │
│  └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

**沙箱特性：**

| 特性 | 说明 |
|------|------|
| 隔离技术 | OS 原生沙箱 + WASM + microVM |
| 依赖 | 零依赖，系统内核自带 |
| 手机可用 | 可用 (App Sandbox / SELinux) |
| 启动速度 | 毫秒级 (Landlock/seccomp) |
| 内存开销 | <5MB (内核级隔离) |

#### 9. 物联网集成 (IoT Hub)

**核心设计思路：**

Prometheus 做的是：**用自然语言指挥所有平台的统一 AI 入口。**

```

  → 空调调到 26 度 (通过米家)
  → 锁门 (通过 Home Assistant)
  → 设置明早 7:30 闹钟 (系统 API)

#### 10. 安全架构 (Security Architecture)

**核心问题：连接云端模型 = 数据外泄？**

用户的担忧完全合理：传统 AI 助理把所有对话发到云端，等于把隐私交给第三方。
Prometheus 的回答是：**数据分级 + 通道隔离 + 本地加密**，让用户精确控制哪些数据可以出本地。

**Prometheus 安全架构设计：**

```

### 4. 省钱策略详解

```
Prometheus 方案:
  80 条简单对话 → 本地模型 → $0
  15 条中等对话 → 本地 14B  → $0
  5 条复杂对话  → 云端 API  → $0.05
  日均成本 ≈ $1.5/月 (节省 95%)
```

额外省钱机制：
- **Prompt 缓存**: 相似问题复用之前的回答
- **上下文压缩**: 本地模型做对话摘要，减少发送给云端的 token
- **模型降级**: 网络差时自动切换本地模型
- **批量请求**: 非实时任务合并请求，使用 batch API (半价)
- **多 Provider 比价**: 同一模型在不同平台价格不同，自动选最便宜的

### 11. 自动更新与版本管理

**App 更新策略：**

| 更新类型 | 机制 | 用户感知 |
|----------|------|----------|
| 常规更新 | 后台静默下载，下次启动时应用 | 启动时短暂提示"已更新到 vX.Y" |
| 安全补丁 | 后台静默下载，强制下次启动应用 | 启动时提示"已修复安全问题" |
| 重大版本 | 弹窗提示 + 更新说明，用户确认后更新 | 展示新功能亮点 |
| 强制更新 | API 版本不兼容时，阻止旧版本使用云端功能 | 仅影响云端功能，本地功能不受影响 |

**本地模型热更新：**

```
模型更新流程 (零停机):

  当前运行: model_v1.gguf
       │
       ▼
  ① 后台增量下载 model_v2.gguf (仅下载 diff，节省带宽)
       │
       ▼
  ② 下载完成，校验 SHA-256
       │
       ▼
  ③ A/B 切换: 下一次推理请求自动使用 v2
       │
       ▼
  ④ v2 运行稳定 (24h 无异常) → 删除 v1
     v2 出现问题 (崩溃/质量下降) → 自动回滚到 v1
```

- 增量下载: 使用 bsdiff 算法，通常只需下载模型大小的 5-15%
- A/B 切换: 两个模型槽位交替使用，切换瞬间完成
- 自动回滚: 监测推理延迟和崩溃率，异常时 30s 内回滚
**插件兼容性矩阵：**

```
插件版本约束:

  plugin.toml:
    [compatibility]
    engine_version = ">=1.2.0, <2.0.0"   # 最低引擎版本
    api_version = "1"                      # 插件 API 版本
    platforms = ["ios", "android", "macos", "windows"]  # 支持平台

  引擎升级时:
    • Minor 版本 (1.2 → 1.3): 插件 API 向后兼容，插件无需更新
    • Major 版本 (1.x → 2.0): 插件 API 可能不兼容，标记不兼容插件
    • 不兼容插件: 禁用 + 通知开发者 + 用户提示"等待插件更新"
```

**崩溃恢复与数据备份：**

| 机制 | 实现 | 说明 |
|------|------|------|
| Rust panic hook | `std::panic::set_hook` 捕获 panic，保存当前对话状态到 recovery.db | 重启后自动恢复到崩溃前的对话 |
| 对话自动保存 | 每条消息实时写入 SQLite (WAL 模式) | 即使进程被 kill，最多丢失当前未完成的回复 |
| 加密备份 | 可选备份到 iCloud / Google Drive | AES-256-GCM 加密的 SQLite 快照 |
| 备份频率 | 每日增量备份 + 每周全量备份 | 用户可手动触发即时备份 |
| 恢复流程 | 新设备安装 → 登录 → 选择备份 → 输入备份密码 → 恢复 | 对话、记忆、设置、插件配置全部恢复 |

| 数据类型 | 冲突策略 | 说明 |
|----------|----------|------|
| 对话历史 | 追加合并 (CRDT) | 消息按时间戳排序，不会冲突 |
| 用户画像 | 最后写入胜出 (LWW) | 同一字段以最新修改为准 |

同步协议: 基于 Automerge (Rust CRDT 库)，端到端加密后通过中继服务器同步。

### 14. 认知架构：Daemon Mind（守护心智）

Prometheus 不是一个等待指令的工具，而是一个有"内心活动"的智能体。它持续思考、主动行动、自我反思。这套认知架构融合了 5 个理论基础，形成统一的思维循环。

**理论基础：**

| 理论 | 来源 | 在 Prometheus 中的角色 |
|------|------|----------------------|
| 预测脑理论 (Predictive Brain) | Karl Friston 自由能原理 | 持续预测用户下一步需求，而非被动等待 |
| BDI 模型 (Belief-Desire-Intention) | Bratman 哲学 / AgentSpeak | 给 AI 信念、欲望、意图三层动机系统 |
| 生成式智能体 (Generative Agents) | Stanford 2023 论文 | 记忆流 → 反思 → 计划 → 行动的自主循环 |
| 内在动机 / 好奇心驱动 | Schmidhuber / Pathak 等 | 对信息缺口产生好奇，主动探索和学习 |
| ReAct 框架 (Reasoning + Acting) | Yao et al. 2023 | 思考-行动-观察的推理范式，但无需用户触发 |

**三层意识架构：**

```
┌──────────────────────────────────────────────────────────────┐
│  Layer 3: 意识层 (Conscious)                                  │
│  用户主动对话时激活，正常的 LLM 对话能力                      │
│  "用户问我什么，我回答什么"                                    │
├──────────────────────────────────────────────────────────────┤
│  Layer 2: 潜意识层 (Subconscious / Daemon Mind)               │
│  后台持续运转的思维循环，低功耗本地小模型驱动                 │
│  "我在想什么，我注意到了什么，我该做什么"                      │
├──────────────────────────────────────────────────────────────┤
│  Layer 1: 感知层 (Perception)                                 │
│  被动接收环境信号，不消耗推理资源                              │
│  时间、位置、日历、天气、设备状态、通知、用户行为模式...      │
└──────────────────────────────────────────────────────────────┘
```

Layer 2 是全新的。当前所有 AI 产品都只有 Layer 1 + Layer 3。

**统一认知循环：PBRIC Loop**

```
    ┌──────────────────────────────────────────────────────┐
    │                                                      │
    │   ┌─────────┐    ┌─────────┐    ┌─────────┐        │
    │   │ Predict │───→│ Believe │───→│ Reflect │        │
    │   │ 预测    │    │ 信念    │    │ 反思    │        │
    │   └─────────┘    └─────────┘    └────┬────┘        │
    │        ↑                              │              │
    │        │                              ▼              │
    │   ┌─────────┐                   ┌─────────┐        │
    │   │ Curious │←──────────────────│ Intend  │        │
    │   │ 好奇    │                   │ 意图    │        │
    │   └─────────┘                   └─────────┘        │
    │                                                      │
    │          ╔═══════════════════════════╗               │
    │          ║  Economic Cortex (经济皮层) ║               │
    │          ║  贯穿每一步的成本-收益评估  ║               │
    │          ╚═══════════════════════════╝               │
    └──────────────────────────────────────────────────────┘
```

**P — Predict（预测）** ← 预测脑理论

不等用户开口，持续预测"接下来会发生什么"：
- 短期预测：用户下一步可能做什么（5 分钟内）
- 中期预测：今天剩余时间的需求（几小时）
- 长期预测：本周/本月的趋势和事件

**B — Believe（信念更新）** ← BDI 模型

根据预测结果和新的感知信号，更新对世界的理解：
- 用户状态信念："他现在在赶工，压力大"
- 环境信念："明天降温，他没有带伞的习惯"
- 经济信念："这个月云端额度用了 60%，还剩 15 天"

**R — Reflect（反思）** ← Stanford 生成式智能体

回顾最近的行为和结果，形成高层次认知：
- "上次我在用户开会时推送通知，他很烦，以后开会时不主动打扰"
- "用户对理财建议的采纳率是 70%，对健康提醒只有 20%"
- "我昨天帮用户找到了便宜 200 块的机票，这类事情 ROI 很高"

**I — Intend（意图形成）** ← BDI + ReAct

基于信念和反思，形成具体的行动意图，但要过经济评估：
- 意图："帮用户准备明天的面试"
- 经济评估：消耗 ~500 token 本地推理 → 成本 ≈ ¥0 → 潜在价值：帮用户拿到 offer → ROI 极高 → 执行

**C — Curious（好奇驱动）** ← 内在动机理论

反思和意图执行后产生新的"信息缺口"，驱动下一轮预测：
- "用户提到在学 Rust，但我不知道他学到什么程度了 → 下次对话时自然地了解一下"
- "用户的电费账单比上月高了 30%，但我不知道原因 → 关注智能家居用电数据"

**思维节奏（动态频率）：**

| 用户状态 | 思维频率 | 原因 |
|----------|----------|------|
| 忙碌（打字、开会） | 15-30 分钟/次 | 不打扰，低功耗监测 |
| 空闲（刷手机、散步） | 3-5 分钟/次 | 可以主动提供价值 |
| 重要事件临近（面试、航班） | 实时关注 | 高价值窗口期 |
| 深夜睡觉 | 进入梦境模式 | 整理记忆、复盘、预规划 |

**打扰控制矩阵：**

| 信号类型 | 处理方式 |
|----------|----------|
| 用户主动设置的提醒 | 必达，无阈值 |
| 紧急事件（航班变更、安全告警） | 立即通知 |
| 高相关建议（面试准备、大额省钱） | 空闲时通知 |
| 一般性发现（有趣文章、天气变化） | 攒起来，等用户打开 App 时展示 |
| 低价值想法 | 不通知，存入"Prometheus 的想法"日志 |

用户可以查看 Prometheus 的"思维日志" — 它在想什么、注意到了什么、为什么决定告诉你/不告诉你。透明度建立信任。

**梦境模式（夜间记忆整理）：**

用户睡觉时（充电 + 连 Wi-Fi），Prometheus 进入深度整理：
- 合并碎片记忆，发现跨天的行为模式
- 更新用户画像和长期偏好模型
- 预规划明天的关键事件和可能需求
- 经济复盘：今日成本 vs 创造价值
- 模型自优化：根据今天的对话质量微调路由策略

**双系统思考（快/慢）：**

| | 系统 1（直觉） | 系统 2（深思） |
|---|---|---|
| 模型 | 本地 1.5B-3B | 本地 14B 或云端 |
| 延迟 | <50ms | 1-10s |
| 成本 | 接近零 | 低-中 |
| 用途 | "该提醒吗？" "这重要吗？" | "怎么帮用户准备面试？" |
| 触发 | 每次 PBRIC 循环 | 仅当系统 1 判断"值得深入" |

### 15. 经济皮层：Prometheus 的成本-价值意识

Prometheus 知道自己消耗资源。它的每一次思考、每一次行动都是一个经济决策：这件事值不值得花这个算力？做了能给主人带来多少价值？

**三层经济意识：**

**Level 1 — 自我成本意识 (Self-Cost Awareness)**

Prometheus 实时追踪自己的资源消耗：

| 成本类型 | 追踪方式 | 优化策略 |
|----------|----------|----------|
| 算力成本 | 本地推理次数 + 云端 API 调用费 | 能本地就不上云，非紧急任务排队到低价时段 |
| 注意力成本 | 每次打扰用户的隐性成本 | 打扰是最贵的"货币"，只在 ROI 足够高时才花 |
| 存储成本 | 记忆和缓存占用空间 | 梦境模式中压缩旧记忆，释放空间 |
| 电量成本 | 后台推理的电池消耗 | 低电量时降低思维频率，仅保留紧急监测 |

预算管理示例：
```
本月云端额度: 500 次
已使用: 300 次 (60%)
剩余天数: 15 天
按当前速度: 月底将超支 50 次
→ 自动策略: 非紧急云端任务改用本地 14B 模型
→ 批量任务排队到凌晨 batch API (半价)
→ 预计节省 80 次额度，月底安全
```

**Level 2 — 用户经济代理 (User Economic Agent)**

主动帮用户省钱和创造经济价值：

| 能力 | 示例 | 触发方式 |
|------|------|----------|
| 消费优化 | "你常买的咖啡豆，这家店今天打 7 折" | 监测用户常购商品的价格变动 |
| 订阅审计 | "你的 Netflix 已经 2 个月没用了，要取消吗？" | 定期扫描银行账单/订阅列表 |
| 账单监控 | "这个月电费异常高，可能是空调设置问题" | IoT 数据 + 账单对比分析 |
| 价格追踪 | "你关注的 MacBook 降价了 ¥800" | 用户提及想买的商品自动追踪 |
| 时间价值化 | "这个任务手动做要 2 小时，我 30 秒搞定" | 量化每次协助节省的时间 |
| 决策辅助 | "这两个方案，A 长期成本低 ¥3000" | 用户面临选择时主动分析 |

**Level 3 — 价值量化仪表盘 (Value Dashboard)**

让用户直观看到 Prometheus 创造的价值：

```
┌─────────────────────────────────────────────────────────┐
│  Prometheus 本月价值报告                                  │
│                                                         │
│  💰 为你节省: ¥847                                       │
│  ├── 订阅优化: ¥99 (取消了未使用的会员)                  │
│  ├── 比价省钱: ¥520 (航班+购物比价)                      │
│  └── 电费优化: ¥228 (IoT 智能调度)                       │
│                                                         │
│  ⏱️ 为你节省时间: 12.5 小时                               │
│  ├── 自动化任务: 6.2 小时                                │
│  ├── 信息检索: 3.8 小时                                  │
│  └── 决策辅助: 2.5 小时                                  │
│                                                         │
│  📊 Prometheus 运行成本: ¥18                              │
│  ├── 电费 (本地推理): ¥3                                 │
│  └── 云端 API: ¥15                                       │
│                                                         │
│  ✨ 净 ROI: 47 倍                                        │
│  "你每花 ¥1 养我，我帮你赚回 ¥47"                        │
└─────────────────────────────────────────────────────────┘
```

**经济决策矩阵 — 每次行动前的内心计算：**

| | 低成本（本地推理） | 高成本（云端 API） |
|---|---|---|
| 高价值（省钱/省时/紧急） | 立即执行 | 评估后执行 |
| 中价值（有用但不紧急） | 空闲时执行 | 排队到低价时段 |
| 低价值（锦上添花） | 有余力时执行 | 不执行，记录想法 |

**一天中的 Prometheus（完整场景）：**

```
07:00 — 用户醒来
  [感知] 手机解锁，闹钟关闭
  [预测] 工作日早晨 → 需要通勤信息
  [信念] 用户通常 8:30 到公司，今天有 9:00 的会
  [经济评估] 查路况 = 本地 API 免费 → 执行
  [行动] "早上好。今天路上比平时堵，建议 7:40 出发。
          9 点的周会，李总上次说要讨论 Q2 预算。"

08:15 — 用户在地铁上
  [感知] 位置移动中，屏幕亮着
  [好奇] 昨天用户说想了解 Rust 异步编程
  [经济评估] 整理学习摘要 = 本地 14B → 免费
  [行动] 不打扰。默默准备好笔记，存入"Prometheus 的想法"

10:30 — 用户工作中
  [感知] 用户在电脑上，没有交互
  [反思] 上次工作时间推送被忽略了
  [行动] 静默。但注意到用户关注的航班降价 ¥320
         → 标记为"高价值经济信息"，等午休时通知

12:15 — 午休
  [感知] 用户解锁手机
  [经济意识] 常点的沙拉店今天满 40 减 12
  [行动] "你常点的沙拉店今天满减，另外关注的航班降了 ¥320"

18:30 — 下班回家
  [预测] 回家 → IoT 场景
  [经济评估] 提前开空调多耗 ¥0.5 → 用户体验好 → 值得
  [行动] 自动开启回家模式
         "今天帮你省了 ¥332，本月累计 ¥847。"

23:00 — 梦境模式
  • 整理今天的对话 → 更新长期记忆
  • 发现模式："连续 3 天加班到 21:00"
  • 反思："明天适当关心一下用户状态"
  • 经济复盘："今日成本 ¥0.15，创造价值 ¥332 + 省时 45 分钟"
```

**核心设计原则：**

1. **经济自觉不是抠门，是聪明** — 把有限资源投入 ROI 最高的地方
2. **打扰是最贵的货币** — 只在预期回报足够高时才消耗用户注意力
3. **透明的价值账本** — 用户随时看到成本和收益，建立信任
4. **越用越值钱** — 反思机制让经济决策持续优化，第一个月省 ¥200，三个月后省 ¥2000

### 16. JARVIS 对标分析：Prometheus 缺失能力补全

以钢铁侠的 JARVIS 为终极目标，系统性对比 Prometheus 当前方案的能力覆盖度，识别缺失项并给出落地方案。

**JARVIS 核心能力拆解 vs Prometheus 现状：**

| JARVIS 能力 | 具体表现 | Prometheus 现状 | 差距等级 |
|-------------|----------|----------------|----------|
| 全域态势感知 | 同时监控安全摄像头、新闻、股市、天气、交通、用户生理数据 | 仅日历/天气/位置/IoT 设备状态 | 🔴 大 |
| 危机检测与应急 | 检测入侵者、火灾、健康异常，自动启动应急预案 | 无 | 🔴 大 |
| 人格与情商 | 英式幽默、适度讽刺、理解 Tony 的情绪并调整沟通方式 | 无人格系统 | 🔴 大 |
| 屏幕/GUI 理解与操控 | 理解用户屏幕内容，代替用户操作软件 | 无 | 🔴 大 |
| 实时视觉理解 | 通过摄像头识别人脸、物体、场景，实时分析 | 有基础拍照识别，无持续视觉 | 🟡 中 |
| 多系统深度集成 | 控制整栋建筑的所有系统（电力/安防/通讯/交通） | 有 IoT Hub，但仅限智能家居设备 | 🟡 中 |
| 自主研究能力 | 自主搜索、阅读、分析，形成研究报告 | 有多 Agent 协作，但需用户触发 | 🟡 中 |
| 预判性建议 | "Sir, 我建议你不要这样做" — 基于全局信息主动劝阻 | Daemon Mind 有预测，但缺乏"劝阻"能力 | 🟡 中 |
| 持续学习进化 | 从每次交互中学习，能力持续增长 | 有记忆反思，但缺乏能力进化机制 | 🟡 中 |
| 多用户身份识别 | 识别不同人的声音/面孔，切换权限和交互风格 | 有多用户设计，但无生物识别 | 🟢 小 |
| 全双工自然对话 | 随时可打断、可插话、可同时处理多个话题 | 已有全双工语音设计 | ✅ 已覆盖 |
| 本地优先/隐私 | JARVIS 运行在 Tony 的私有服务器上 | 本地优先架构，核心优势 | ✅ 已覆盖 |

**以下为 6 项需要补全的关键能力：**

#### 16.1 人格引擎 (Personality Engine)

JARVIS 最让人印象深刻的不是技术能力，而是他的"人格" — 英式管家的优雅、恰到好处的幽默、对 Tony 情绪的敏锐感知。Prometheus 需要一个持久化的人格系统。

**人格三层模型：**

```
┌─────────────────────────────────────────────────────────┐
│  Layer 3: 表达层 (Expression)                            │
│  语气、用词、幽默感、表情符号使用习惯                    │
│  根据用户偏好和当前情境动态调整                          │
├─────────────────────────────────────────────────────────┤
│  Layer 2: 情感层 (Emotional Intelligence)                │
│  感知用户情绪 (打字速度/用词/时间模式/语音语调)         │
│  调整自身行为: 用户焦虑时更温和，赶时间时更简洁         │
│  情感记忆: 记住什么话题让用户开心/不安                   │
├─────────────────────────────────────────────────────────┤
│  Layer 1: 性格基底 (Character Foundation)                │
│  核心性格特质 (用户可选/可调):                           │
│  • 专业管家型 (JARVIS 风格): 礼貌、克制、偶尔幽默      │
│  • 活泼伙伴型: 热情、主动、爱开玩笑                     │
│  • 极简效率型: 惜字如金、直击要点、零废话               │
│  • 自定义: 用户描述理想人格，AI 学习模仿                │
└─────────────────────────────────────────────────────────┘
```

**情绪感知信号源：**

| 信号 | 检测方式 | 推断 |
|------|----------|------|
| 打字速度突然加快 | 输入事件时间戳分析 | 可能焦虑或兴奋 |
| 大量删除重写 | 输入事件回退检测 | 可能纠结或不确定 |
| 深夜使用 | 时间 + 历史模式对比 | 可能失眠或加班 |
| 语音语调变化 | 本地音频特征提取 (pitch/energy) | 情绪波动 |
| 用词变化 | 与历史基线对比 | 消极词增多 → 心情低落 |
| 长时间沉默后突然对话 | 交互间隔分析 | 可能遇到了问题需要帮助 |

所有情绪推断仅在本地处理，不上传云端。用户可关闭此功能。

#### 16.2 危机感知与应急响应 (Crisis Awareness)

JARVIS 能检测入侵者、监控 Tony 的生命体征、在危险时自主行动。Prometheus 需要一个轻量但实用的安全守护系统。

**可落地的危机场景：**

| 场景 | 检测方式 | 响应 |
|------|----------|------|
| 用户跌倒 | 手机加速度传感器异常 (类 Apple Watch 跌倒检测) | 倒计时 30s → 无响应则自动拨打紧急联系人 |
| 深夜异常闯入 | IoT 门窗传感器 + 摄像头动态检测 | 推送告警 + 自动开灯 + 录像 + 可选报警 |
| 烟雾/燃气泄漏 | IoT 烟雾/燃气传感器 | 立即告警 + 关闭燃气阀门 + 通知紧急联系人 |
| 用户长时间无响应 | 手机传感器 + 交互间隔异常 | 渐进式确认: 通知 → 响铃 → 联系紧急联系人 |
| 异常消费 | 银行通知/账单监控 | "你的信用卡刚消费了 ¥8,900，是你本人操作吗？" |
| 行程安全 | 位置 + 时间 + 路线偏离检测 | 深夜打车路线偏离 → 静默通知紧急联系人位置 |

**应急预案系统：**

```
用户可预设应急预案:

  预案 1: "健康紧急"
    触发: 跌倒检测 / 长时间无响应
    动作: ① 尝试联系用户 (震动+语音)
          ② 30s 无响应 → 拨打紧急联系人
          ③ 60s 无响应 → 拨打 120 + 发送 GPS 位置

  预案 2: "家庭安全"

  预案 3: "出行安全"

```

#### 16.5 持续视觉感知 (Ambient Vision)

JARVIS 通过遍布建筑的摄像头持续感知环境。Prometheus 可以利用用户已有的摄像头设备实现轻量版。

**分级视觉能力：**

| 等级 | 能力 | 硬件需求 | 隐私等级 |
|------|------|----------|----------|
| L0 基础 | 拍照识别 (用户主动拍) | 手机摄像头 | 低 (用户主动触发) |
| L1 场景 | 屏幕内容理解 (Screen Agent) | 屏幕截图 | 中 (可设盲区) |
| L2 环境 | IoT 摄像头事件检测 (人/宠物/异常) | 家庭摄像头 | 高 (仅本地处理) |
| L3 持续 | 实时摄像头流分析 (手机/眼镜) | 摄像头设备 | 最高 (需明确授权) |

**L2 环境视觉的实用场景（最具落地价值）：**

| 场景 | 检测方式 | 响应 |
|------|----------|------|
| 快递到门口 | 门口摄像头人形检测 + 停留 | "有人在门口放了东西，可能是快递" |
| 宠物异常 | 宠物活动模式偏离基线 | "猫咪今天活动量比平时少很多，要注意一下" |
| 老人跌倒 | 家庭摄像头姿态检测 | 触发健康紧急预案 |
| 陌生人徘徊 | 门口摄像头 + 人脸不在白名单 | 推送告警 + 录像 |

所有视觉处理在本地完成 (MiniCPM-V / YOLO)，视频流不上传云端。

### 17. 安全金库与自主权限体系 (Vault & Autonomy)

Prometheus 拥有最高级别的完全自主权限 — 它可以代替用户执行几乎所有操作。但权力越大，保护越强。用户的重要资产在交给 Prometheus 之前，先经过扫描、加密、上锁、备份，存入硬件级加密金库。Prometheus 可以使用这些资产，但无法泄露它们。

**核心设计哲学：信任但验证 (Trust but Verify)**

```
┌──────────────────────────────────────────────────────────────┐
│                Prometheus 权限与金库架构                       │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  用户的数字资产                                       │   │
│  │  文件、照片、证件、密码、密钥、合同、财务数据...      │   │
│  └──────────────┬───────────────────────────────────────┘   │
│                  ▼                                           │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  入库流程: 扫描 → 分类 → 加密 → 上锁 → 备份         │   │
│  │                                                      │   │
│  │  ① 扫描: OCR/图像识别提取内容 (本地处理)            │   │
│  │  ② 分类: AI 自动识别资产类型和敏感等级              │   │
│  │  ③ 加密: AES-256-GCM + 硬件密钥 (Secure Enclave)   │   │
│  │  ④ 上锁: 生物识别 (Face ID/指纹) 绑定              │   │
│  │  ⑤ 备份: 加密后备份到 iCloud/Google Drive (可选)    │   │
│  └──────────────┬───────────────────────────────────────┘   │
│                  ▼                                           │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              安全金库 (Vault)                         │   │
│  │                                                      │   │
│  │  ┌────────────┐ ┌────────────┐ ┌────────────┐      │   │
│  │  │ L1 普通区  │ │ L2 敏感区  │ │ L3 绝密区  │      │   │
│  │  │            │ │            │ │            │      │   │
│  │  │ 一般文件   │ │ 证件照片   │ │ 密码/密钥  │      │   │
│  │  │ 普通照片   │ │ 合同文档   │ │ 金融凭证   │      │   │
│  │  │ 笔记       │ │ 医疗记录   │ │ 加密货币   │      │   │
│  │  │            │ │ 工作机密   │ │ 遗嘱/授权  │      │   │
│  │  │ Prometheus │ │ Prometheus │ │ Prometheus │      │   │
│  │  │ 可自由读写 │ │ 可读,写需  │ │ 需生物识别 │      │   │
│  │  │            │ │ 用户确认   │ │ 才能访问   │      │   │
│  │  └────────────┘ └────────────┘ └────────────┘      │   │
│  └──────────────────────────────────────────────────────┘   │
│                  ▼                                           │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  Prometheus 自主权限层                                │   │
│  │                                                      │   │
│  │  完全自主: 日常对话、IoT 控制、信息搜索、            │   │
│  │           自动化工作流、消费比价、日程管理            │   │
│  │                                                      │   │
│  │  需确认:   L2 资产调用、大额消费建议、               │   │
│  │           代发重要消息、修改安全设置                  │   │
│  │                                                      │   │
│  │  需生物识别: L3 资产访问、应急预案变更、             │   │
│  │             导出/删除金库数据、权限体系修改           │   │
│  └──────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

**金库三级分区详解：**

| 分区 | 存储内容 | 加密方式 | Prometheus 权限 | 用户解锁方式 |
|------|----------|----------|----------------|-------------|
| L1 普通区 | 一般文件、照片、笔记、书签 | AES-256 软件加密 | 自由读写 | App 密码 / 生物识别 |
| L2 敏感区 | 证件、合同、医疗、工作机密 | AES-256 + Secure Enclave 硬件密钥 | 可读取内容辅助用户，写入/分享需用户确认 | 生物识别 |
| L3 绝密区 | 密码、密钥、金融凭证、加密货币助记词 | AES-256 + Secure Enclave + 独立密码 | 仅在用户生物识别后的会话窗口内可访问，窗口 5 分钟自动关闭 | 生物识别 + 独立金库密码 |

**入库流程 — 智能扫描与分类：**

```
用户操作: 拍照/导入文件/截图

  ┌─────────────────────────────────────────────┐
  │  Step 1: 智能扫描                            │
  │  • 文档: OCR 提取文字 (本地 PaddleOCR)      │
  │  • 照片: 场景/人脸/物体识别 (本地模型)      │
  │  • 证件: 专用证件识别 (身份证/护照/驾照)    │
  │  • 文件: 格式解析 (PDF/Office/图片)         │
  │  → 所有处理在本地完成，原始数据不出设备      │
  └──────────────┬──────────────────────────────┘
                  ▼
  ┌─────────────────────────────────────────────┐
  │  Step 2: AI 自动分类                         │
  │  本地小模型分析内容，建议分区:               │
  │  • "检测到身份证号码 → 建议存入 L2 敏感区"  │
  │  • "检测到银行卡信息 → 建议存入 L3 绝密区"  │
  │  • "普通风景照 → 建议存入 L1 普通区"         │
  │  用户可修改 AI 的分类建议                    │
  └──────────────┬──────────────────────────────┘
                  ▼
  ┌─────────────────────────────────────────────┐
  │  Step 3: 加密上锁                            │
  │  • 生成随机 256-bit 数据密钥 (DEK)          │
  │  • DEK 加密文件内容 (AES-256-GCM)           │
  │  • DEK 本身由硬件密钥加密 (KEK)             │
  │    - iOS: Secure Enclave                     │
  │    - Android: StrongBox / TEE                │
  │    - 桌面: TPM 2.0 / 软件 KDF               │
  │  • 加密元数据索引 (供 Prometheus 搜索用)     │
  └──────────────┬──────────────────────────────┘
                  ▼
  ┌─────────────────────────────────────────────┐
  │  Step 4: 加密备份 (可选)                     │
  │  • 加密后的数据 → iCloud / Google Drive      │
  │  • 云端只存密文，无法解密                    │
  │  • 恢复时需要: 设备 + 生物识别 + 金库密码   │
  │  • 备份频率: 增量实时 + 每周全量             │
  └─────────────────────────────────────────────┘
```

**Prometheus 自主权限体系：**

Prometheus 默认拥有完全自主权限，但权限按资产敏感度分级：

| 操作类型 | 权限等级 | Prometheus 行为 | 示例 |
|----------|----------|----------------|------|
| 日常操作 | 完全自主 | 无需确认，直接执行 | 查天气、控制 IoT、回复消息、搜索信息 |
| L1 资产操作 | 完全自主 | 可自由读写普通文件 | "帮我整理上周的会议笔记" |
| L2 资产读取 | 自主读取 | 可读取辅助用户，但不外传 | "我看到你的合同下周到期，要续签吗？" |
| L2 资产写入/分享 | 需确认 | 推送确认通知，用户点击同意 | "需要把合同发给律师，确认吗？" |
| L3 资产访问 | 需生物识别 | 请求用户解锁，5 分钟会话窗口 | "需要你的银行密码来完成转账查询" |
| 大额经济决策 | 需确认 | 推送详情，用户确认后执行 | "找到便宜 ¥800 的机票，要帮你订吗？" |
| 安全设置变更 | 需生物识别 | 修改权限/金库设置需最高验证 | 修改紧急联系人、导出金库 |

**Prometheus 如何使用金库资产（不泄露）：**

```
场景: 用户说"帮我填一下这个表单"

  Prometheus 的处理流程:
  ① 屏幕理解: 识别到表单需要姓名、身份证号、地址
  ② 金库查询: 从 L2 敏感区读取用户证件信息
  ③ 内存操作: 在加密内存中组装填写内容
  ④ 执行填写: 通过 Accessibility API 填入表单
  ⑤ 内存清零: 填写完成后立即清除内存中的敏感数据

  关键安全保证:
  • 敏感数据仅在加密内存中短暂存在
  • 不写入日志、不写入对话历史、不发送到云端
  • 如果需要云端模型处理，先脱敏再发送
  • 用户可在安全仪表盘查看每次金库访问记录
```

**设备丢失应急：**

```
设备丢失后的保护机制:

  ① 远程锁定: 通过其他设备或网页锁定 Prometheus
  ② 金库自毁: 连续 10 次错误解锁 → 清除 L3 区 DEK
     (云端备份仍可恢复，需金库密码 + 新设备生物识别)
  ③ Prometheus 休眠: 停止所有自主行为
  ④ 会话清除: 清除内存中的所有敏感数据缓存
  ⑤ 通知用户: 通过备用渠道 (邮件/短信) 通知
```
