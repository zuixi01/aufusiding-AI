# 功能状态与已知限制

本文描述当前代码的接入范围，用于区分「模块已存在」和「用户能够通过入口完成任务」。它不是发布认证或固定测试数量声明。实际兼容性以对应提交的 CI 和平台验证为准；历史设计、研究和计划文档不能替代运行结果。

## 当前定位

项目处于 **早期 Alpha**。推荐的首条体验路径是 [CLI + Ollama](getting-started.md)。欢迎开发者试用、验证与贡献；接口、模型标识和本地数据结构仍可能变化。升级前请备份本地会话。

项目对外名称为 aufusiding-AI，内部继续使用 Prometheus AI，包括 Rust crate 的 `prometheus-*`、CLI 二进制 `prometheus`、服务端二进制 `prometheus-server` 和本地 `prometheus-ai` 配置目录。

## 接入情况

| 范围 | 已有实现与入口 | 当前限制 |
| --- | --- | --- |
| CLI 对话 | `ask`、REPL、Ollama Provider、显式 `--mock` | 真实推理需要用户安装和启动 Ollama，并下载正确模型；云端 Provider 未作为 CLI 统一配置入口 |
| 会话 | SQLite 会话与消息持久化、历史查询、导出、归档/清理 | 本地数据可能含原始对话；备份、数据迁移和多用户隔离需进一步完善 |
| 模型管理 | `ask --model`、REPL `/switch`、`config set default_model` | `model list` 为静态列表；`model info`、`model test` 尚未提供真实查询和检测 |
| CLI 配置 | TOML 配置、数据目录、默认模型、历史容量 | 路由策略、预算、token 上限、温度等字段尚未完整接入 CLI 推理执行 |
| CLI 记忆查询 | `query-memory` 检索当前数据目录中的会话消息 | 关键词历史检索，不是完整知识库或向量检索入口 |
| HTTP 服务 | Axum REST、会话/对话/记忆等路由、OpenAPI、健康、指标 | 需要显式配置真实模型、数据持久化和访问控制；默认认证关闭；生产部署未经本轮端到端验收 |
| 云端 Provider | 核心和服务端包含 OpenAI、Anthropic 等 HTTP 适配 | 需有效凭据和供应商模型权限；内置默认云模型可能需通过 `PROMETHEUS_MODEL` 覆盖。混合 Provider 的 fallback 尚未按目标 Provider 重映射模型标识，跨供应商回退可能因模型名不兼容失败；费用和数据外发仍需实际验证 |
| 记忆与路由核心 | 工作记忆、情景记忆、知识库、分类、路由与回退模块 | 不同入口接入范围不同；模块单测不证明所有客户端已具有同等行为 |
| Agent / 环境智能 | 规划、执行、角色、工作流与主动智能相关模块 | 实验性；缺少统一用户入口和完整真实场景验收 |
| 语音 | STT/TTS/唤醒词接口、HTTP 适配与 mock 实现 | 需要独立语音服务、模型和设备；不代表开箱即用的实时语音助手 |
| IoT | 设备、配对、控制和自动化模块 | 默认 `DeviceDiscovery` 扫描使用模拟设备模板；不能视为真实设备发现成功 |
| 插件 | SDK、WASM 运行时、计算器与天气示例 | 天气插件生成确定性的模拟天气，不能提供实况；插件执行和权限仍需逐场景验证 |
| 隐私与安全 | 同意、导出、删除、匿名化、认证与审计等组件 | 组件存在不构成 GDPR 等法规合规保证，也不表示已完成独立安全审计或全部端点权限验收 |
| 桌面端 | Tauri 后端与单文件 HTML/CSS/JavaScript 前端、Vite 构建 | 实验性；模型 ID 硬编码，Ollama 不可达时仍自动 mock 回退；自动设置依赖 `which`/`sh`。原生启动、Windows 设置与安装包仍需独立验证，见 [桌面端说明](../apps/desktop/README.md) |
| iOS / macOS / Android / FFI | SwiftUI、Compose、UniFFI 和平台脚本 | 需对应 SDK、签名和设备；源码存在不构成已验证的平台支持 |
| Docker 与发布流程 | 镜像、Compose 和 GitHub Actions 配置 | 配置文件存在不表示镜像已发布，或当前提交已通过部署、升级和回滚验证 |

## 本轮验收边界

开源整理首先改善可复现的 CLI 入门、模拟与真实推理的区分、文档一致性和自动检查配置。不要把下列事项写成已验证事实，除非为当前提交补充实际证据：

- Ollama 的真实模型质量、吞吐量、首 token 延迟或跨硬件基准。
- 本地对话占比、费用节约、预算强制执行或自动云端路由的收益。
- 桌面端原生打包、移动端设备运行、真实语音和 IoT 设备控制。
- 公网运行、TLS、多人共享、数据迁移、灾难恢复或法规符合性。
- 固定数量的测试全部通过，或没有已知依赖风险。

本机 mock 流程能验证交互和持久化的一部分，不能替代真实模型、真实设备或部署验收。健康接口可访问也不能证明 Provider 已完成一次真实对话。

## 贡献方向

依赖审计已修复本轮检出的 zip 漏洞，但仍有未维护依赖和 Linux 桌面链上的 glib unsound 警告；详见 [依赖审计记录](dependency-status.md)。审计命令通过不等于已完成安全影响分析。

适合优先推进的工作包括：补齐明确标注的占位功能、隔离测试副作用、完善真实 Provider 的错误信息和回归测试、验证某一具体平台、修复文档与实际行为的差异。请遵循 [贡献指南](../CONTRIBUTING.md)，在 PR 中列出实际验证和仍未覆盖的范围。
